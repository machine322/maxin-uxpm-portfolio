EXPERIENCE DIAGNOSIS FRAMEWORK

从用户问题，
走到可验证的产品决策。

一条贯穿研究、旅程、产品结构和体验度量的诊断路径。它是从多个真实项目抽象出的工作框架；每个项目只展示材料能够支撑的环节与结果。

01 / DIAGNOSIS PATH

问题如何进入产品决策

七步方法用于帮助团队对齐问题和验证方式；不表示每个历史项目都执行了完整七步。

01 / DETECT

发现

汇总反馈、工单、走查和业务信号。

VOC · 体验问题池
02 / QUANTIFY

量化

找出问题规模、发生环节与流失位置。

漏斗 · 完成率 · 错误率
03 / UNDERSTAND

理解

通过用户研究解释行为背后的原因。

调研 · 可用性 · 竞品
04 / STRUCTURE

重构

建立用户旅程、任务层级与信息架构。

Journey · IA · 状态
05 / DESIGN

设计

把洞察转成场景方案、交互和 PRD。

策略 · 原型 · 需求
06 / VALIDATE

验证

先定义成功指标，再做测试或上线比较。

Usability · A/B · Pre/Post
07 / ITERATE

迭代

回看结果和新反馈，进入下一轮判断。

Issue loop · Release feedback
如何阅读案例：每个项目会标明材料直接记载了什么、我承担了什么、哪些数字只是观察结果，以及还缺少哪些验证条件。

03 / EVIDENCE LEDGER

已有证据与方法建议分开

所有业务指标均为来源文件报告值；缺少样本、窗口、对照等信息处已标出边界。

VERIFIED / SOURCE FACTS

源文件能直接核对

  • VOC 项目完整章节为总集第 20–43 页；覆盖体验分析和界面方案。
  • 合约交易与止盈止损的方案页分别记录版本、交互说明和状态规则。
  • Muse 简历记载目标用户研究、可用性测试、竞品分析、UI / 研发协作与项目上线。
OBSERVED / REPORTED

材料报告的真实结果

  • VIP：使用数据 3.28% → 17.01%（+13.73 个百分点）；充值率 11.74% → 12.98%（原页标 +1.24 个百分点）；投资率 13.62% → 16.73%（+3.11 个百分点）。
  • VOC：23+ 项体验问题、4 处关键流程、日均付费率环比 +49.63%。
  • 模拟返现：20 万新用户样本漏斗；首入金用户 190 人，平均首入金 1,908U，平均体验成本约 57U；≈33×是金额比值，不代表利润或净 ROI。
  • CMBSans：问卷样本 300；简历另记录跨平台效率 +6.2%、品牌辨识度 +15%、信任度 +10%。原始问卷和结果测量口径未提供。
  • 研究机制：问卷回收逾 5,000 份；未注明去重用户量和有效样本量。
FRAMEWORK / NEXT MEASURES

建议后续补齐

  • 行为：关键任务成功、放弃、错误、完成时间和路径长度。
  • 体验：满意度、NPS / CES、反馈主题和投诉率；现有材料没有 NPS 数值。
  • 业务：激活、付费、留存和收入，并区分 cohort 与流量来源。
  • 运营：反馈响应时间、问题关闭率、缺陷复发和客服负荷。
  • 前后比较应保留统一定义、样本范围、观察窗口和同期影响。
HYPOTHESIS / NOT YET TESTED

待验证假设

  • 如果关键任务的下一步和完成状态更清楚，用户中途退出可能减少。
  • 如果风险参数与价格依据在同一上下文展示，用户对触发结果的理解可能提升。
  • 这些是可测试的产品假设，不是本作品集宣称已发生的结果。
A/B Test 能力证据

简历中“增长投放决策引擎”项目记录支持灰度与 A/B Test 能力；不等于本页其他案例做过 A/B Test，也没有相应实验结果、分流方式或显著性资料。
